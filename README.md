# 3D-навигатор по корпусу (первый этаж)

Интерактивная 3D-карта этажа: помещения поднимаются цветными плитами, стены — объёмом,
поиск находит аудиторию по номеру или типу и подсвечивает её, камера подлетает к комнате.
Работает с мышью и с телефона (перетаскивание, щипок для зума, поворот двумя пальцами).

Источник данных — обычный SVG-план из Inkscape (`1floor.svg`), никаких отдельных баз
и координат: имя помещения берётся из `inkscape:label`, форма — из контура.

```
npm install
npm run dev        # http://localhost:5173
```

Сборка и проверка:

```
npm run build      # статика в dist/
npm run preview    # локальный просмотр сборки на :4173
npm test           # быстрые тесты логики (node --test)
npm run test:browser   # сквозная проверка в headless Chrome (нужен запущенный preview)
npm run analyze:svg    # разбор плана как файла: габариты, площади, дефекты контуров
npm run analyze:plan   # что реально построилось из плана в 3D (нужен запущенный preview)
```

## Как устроено

```
1floor.svg              план этажа (правится в Inkscape)
index.html              разметка интерфейса
public/favicon.svg      иконка сайта
src/config.js           размеры, цвета, путь к плану (§ начало файла) — всё, что обычно нужно менять
src/main.js             сцена, камера, выбор помещений, поиск и интерфейс (и импорт плана)
src/core/plan.js        чтение SVG: стены и помещения, метрики (площадь, центр, габарит)
src/core/raster.js      построение «пятна» помещения из контура (растр + заливка + трассировка)
src/core/geometry.js    площади, центры, габариты и перевод координат SVG -> сцена
src/core/build.js       сборка 3D-модели: пол, стены, плиты помещений, контуры, номера
src/core/labels.js      спрайты-подписи с номерами помещений
src/core/rooms.js       типы помещений, разбор имён, поиск, склонения
```

Соответствие координат: `SVG (x, y) -> сцена (x, ·, y)`, высота — вверх по `Y`.
1 единица плана ≈ 0.3 м (типовая аудитория на плане — ~20×23 единицы, то есть ~6 м).

## Как план превращается в 3D

1. В тексте SVG находятся `path`-элементы и читается `inkscape:label`.
2. Элемент с меткой `walls` (или `id="walls"`) считается стенами.
3. Остальные — помещения: имя `тип_номер` разбирается на тип и номера
   (`dep_146_147_148` → «Кафедра 146, 147, 148», поиск найдёт любой из номеров).
4. Геометрия: контур помещения растеризуется так, как его нарисовал бы браузер
   (`Path2D` + `fill-rule`), затем узкие проёмы дверей запечатываются, внутренность
   заливается, а границы плиты возвращаются к исходному контуру. Так одинаково хорошо
   получаются и комнаты, нарисованные линией с проёмом, и комнаты, обведённые «двойной
   линией» (когда контур — это стены вокруг пустой середины).
5. Готовая фигура выдавливается в плиту, стены — в объём, центры фигур используются для
   подписей и перелёта камеры.

Если контур всё-таки не удалось построить, приложение не падает: помещение берётся
как есть, а в консоль и в строку статуса попадает предупреждение (см. `SVG-ISSUES.md`).

## Правка плана

- Подпись помещения: выделить объект → **Объект → Свойства объекта** (`Ctrl+Shift+O`) →
  поле **«Метка»**. Схема: `тип_номер`, например `stud_105`, `dep_146_147_148`, `other_gym`.
- Стены: метка `walls` (плюс желательно `id="walls"`).
- Типы: `stud`, `dep`, `dean`, `admin`, `toilet` + подтипы `gym`, `medical`.
  Русские названия, цвета и синонимы для поиска — в одном месте: `src/core/rooms.js`.
- После правки файла достаточно обновить страницу — план читается при загрузке.
- Что и почему стоит поправить в текущем файле: **[SVG-ISSUES.md](SVG-ISSUES.md)**.

## Отладка

В консоли браузера доступен объект `window.__navigator`:

```js
__navigator.diagnostics()        // сколько помещений, габарит, предупреждения, камера
__navigator.plan.rooms           // все помещения с площадью, центром, радиусом запечатывания
__navigator.pick(x, y)           // какое помещение находится в точке экрана
__navigator.select('stud_105')   // выбрать помещение программно
__navigator.reset()              // вернуть общий вид
```

## Ограничения

- Этаж один; переключателя этажей нет.
- Маршруты и навигация «как пройти» не строятся — только поиск и подсветка.
- Комнаты, перекрывающиеся друг с другом (например комната внутри общего блока),
  разложены по высоте: меньшая плита лежит выше и выбирается первой.
