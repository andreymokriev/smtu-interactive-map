# Что не так с `1floor.svg` и как это поправить руками

Разбор сделан двумя инструментами проекта:

```
npm run analyze:svg     # разбор файла без браузера: габариты, площади, дефекты контуров
npm run build && npm run preview   # в отдельном терминале
npm run analyze:plan    # что реально построилось в 3D из этого файла
```

Текущий итог: **75 элементов `<path>`, из них 1 стены (`walls`) и 73 помещения**.
Все 73 помещения строятся, габарит совпадает с тем, как файл рисует сам браузер,
но несколько мест лучше поправить руками.

## Как приложение читает план

| Что нужно | Где берётся |
| --- | --- |
| Стены | `inkscape:label="walls"` (или `id="walls"`) |
| Помещение | `inkscape:label` вида `тип_номер` — `stud_105`, `dep_146_147_148`, `other_gym` |
| Форма помещения | атрибут `d` вместе с `transform`; заливка строится автоматически |

Подпись меняется в Inkscape так: выделить объект → **Объект → Свойства объекта**
(`Ctrl+Shift+O`) → поле **«Метка» (Label)**. Поле «Идентификатор» (id) роль не играет,
но для стен его тоже стоит выставить в `walls`.

## 1. Помещение без подписи — обязательно исправить

| id | где | что делать |
| --- | --- | --- |
| `path84` | x 507.6…518.4, y 292.2…305.6 — комната между `other_158` и `dep_3_yu` | это полноценная комната 10.8×13.4, но без метки приложение её пропускает и пишет предупреждение |

Дайте ей подпись по схеме (`Объект → Свойства объекта → Метка`), например `dep_180`
или `other_180` — в зависимости от того, что там находится. Если это не помещение
(например фрагмент коридора) — удалите объект.

## 2. Подписи не по схеме «тип_номер»

| Метка | id | Как есть | Что лучше |
| --- | --- | --- | --- |
| `162` | `path52` | потерян тип | `stud_162` (или свой тип) |
| `164` | `path53` | потерян тип | `stud_164` |
| `other_gym` | `path178` | тип + подтип | ок, приложение понимает: «Спортзал» |
| `other_medical_1`, `other_medical_2` | `path15`, `path829` | тип + подтип | ок, приложение понимает: «Медпункт» |
| `walls` | `path1` | — | ок (для стен так и надо) |

`162` и `164` сейчас попадают в тип «Прочее» и называются «Помещение 162».
После правки они станут обычными аудиториями со своим цветом и фильтром.

## 3. Контуры, которые пересекают сами себя — стоит перерисовать

| Метка | id | Признак |
| --- | --- | --- |
| `other_medical_1` | `path15` | самопересечение |
| `other_medical_2` | `path829` | самопересечение |
| `other_112` | `path828` | самопересечение |
| `dep_144` | `path28` | самопересечение, 6 отдельных контуров в одном объекте |
| `other_138` | `path30` | самопересечение, 2 контура |

Такие фигуры — обычно след от экспорта PDF (текст/двойные линии) или случайный «росчерк»
при правке. Приложение заливает их корректно, но форма плиты получается «рваной».
Лечится просто: **нарисовать прямоугольник по внутренним границам комнаты** (инструмент
«Прямоугольник», включите прилипание `%`), удалить старый контур и задать метку новому
объекту. Либо вручную: `Ctrl+Shift+K` (Разбить) → удалить лишние фрагменты →
`Ctrl++` (Объединить).

## 4. Комнаты, нарисованные «двойной линией»

В файле 46 элементов — только обводка (`fill:none`), и 52 контура не замкнуты (в них
проём двери). Часть комнат нарисована замкнутой тонкой рамкой толщиной ~0.36 (это
контур стены, а не площадь комнаты):

`admin_183`, `dep_141`, `dep_143`, `dep_144`, `dep_145`, `dep_146_147_148`, `dep_150`, `toilet_3`

Приложение само заливает внутренность (проверено: площадь плиты теперь совпадает с
габаритом комнаты), так что **исправлять не обязательно**. Если хочется чистого файла
с заполненными областями:

1. выделить рамку;
2. `Ctrl+Shift+K` — «Разбить», если рамка состоит из двух вложенных контуров
   (внешний и внутренний) — так у `dep_143`, `dep_145`, `dep_150`, `dep_146_147_148`, `dep_144`;
3. удалить внутренний контур;
4. на внешнем: `Ctrl++` — «Объединить» (Inkscape закроет и зальёт фигуру);
5. у объектов вида `stud_124` рамка нарисована одним «туда-обратно» контуром —
   такое разбить нельзя, надёжнее нарисовать прямоугольник поверх и задать ему метку.

## 5. Один объект — несколько помещений

| Метка | id | Комментарий |
| --- | --- | --- |
| `dep_146_147_148` | `path23` | три кафедры в одном контуре: в поиске находятся все три, но подсвечиваются одной плитой |
| `other_177_176_175_174` | `path65` | четыре помещения одним контуром |
| `stud_168_138` | `path59` | подозрительно: помещение «138» уже есть отдельно как `other_138` — вероятно опечатка в подписи |

Если нужно находить и подсвечивать их по отдельности — нарисуйте для каждого помещения
свой прямоугольник с собственной меткой и удалите общий контур.

## 6. Мелочи, которые не ломают карту, но мешают

- `dep_1_yu` … `dep_6_yu` — суффикс `yu` приложение игнорирует (показывает «Кафедра 1»,
  «Кафедра 2» …). Если это «Ю-1» и т. п., лучше название писать в поле «Метка» целиком:
  например `dep_yu1` даст «Кафедра 1» — тогда заведите отдельный тип или переименуйте
  суффикс словами.
- `dep_110` и `dep_110a`, `stud_191a`, `other_150a` — буквенные индексы поддерживаются,
  поиск найдёт и «110a», и «110а».
- Некрасиво, но работает: у стен `id="path1"`. Пропишите `id="walls"` — тогда приложение
  найдёт стены, даже если метку случайно переименуют.
- Все помещения лежат в одном слое без имени. Заведите слои «walls», «rooms», «текст» —
  так проще править.

## 7. Чего в файле нет

- **Нет ни одного `<text>`** — номера помещений существуют только в виде меток
  `inkscape:label`. Это нормально: 3D-карта сама рисует номера, но помните, что если
  вы пишете номер текстом в Inkscape, приложение его не увидит — нужна именно метка.
- Нет `viewBox`-запаса: контур `walls` занимает почти всю область (`x 198.6…734.5`,
  `y 139.3…336.1`) — при добавлении новых помещений следите, чтобы они не вылезали за
  границу `0 0 768 576`.

## Чек-лист для второго этажа

1. Скопируйте `1floor.svg` → `2floor.svg` (или нарисуйте новый слой поверх).
2. Стенам — метка `walls`, помещениям — `тип_номер` **без** префикса этажа (`205`, а не `2_205`).
3. Убедитесь, что все объекты — `<path>` в одном слое и что у каждого есть `d`.
4. Проверьте файл: `npm run analyze:svg 2floor.svg` (и `npm run analyze:plan`, подменив план).
5. Подключение второго этажа в коде — одна константа в `src/config.js` (см. README).

После любой правки достаточно обновить страницу: план читается заново при загрузке.
